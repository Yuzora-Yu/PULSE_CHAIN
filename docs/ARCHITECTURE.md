# ルール・実装設計

## モジュール

| ディレクトリ | 役割 |
|---|---|
| `src/core` | 整数座標ルール、状態、イベント、純粋遷移、盤面検証 |
| `src/solver` | BFS / 深さ反復探索。core/transitionだけを使用 |
| `src/generator` | 固定PRNG、連鎖グラフの埋め込み、変異、品質評価、初期ステージ固定 |
| `src/renderer` | DOM盤面、Canvas光球、音声 |
| `src/workers` | 生成・探索のWorkerインターフェース |
| `src/storage` | セーブ移行、ローカル記録、IndexedDBキャッシュ |
| `src/main.ts` | モード・操作・画面・Workerの管理 |
| `src/inspector.ts` | 比較・人間評価用ツール |

## RULE-V1 の確定ルール

1. 直接タップはHPにかかわらず、そのCOREを即座に起爆する。
2. 起爆は8方向へ1個ずつ光球を発射する。各整数tickで1セル進む。
3. tick開始時点で生存しているCOREは、そのtickの命中をすべて吸収する。同時命中数を集計してHPを減らし、0になったCOREをまとめて起爆する。COREの配列順で結果を変えない。
4. 光球同士は衝突しない。盤面外、VOID、BLOCKに到達すると消える。
5. MIRROR `/` は `(dx,dy)→(-dy,-dx)`、`\` は `(dx,dy)→(dy,dx)`。斜めの光も幾何学的な反射に従う。
6. SPLITTERは入射方向、左90度、右90度の3方向へ分岐する。
7. GATEは矢印と同じ**進行方向**の光だけを通す。
8. CHARGEは累積命中数でカウントが0になると一度だけ8方向へ発射し、その後は透明になる。消去対象ではない。
9. ROTATORはtick開始時の向きで全光球を反射し、そのtickの命中数だけ `/` と `\` を切り替える。偶数命中なら向きは同じ。向きは次のタップへ持ち越す。
10. PORTALは対応する同番号の出口へ移動し、向きを維持して次tickで出口の次のセルへ進む。出口のPORTALへ即時再突入しない。
11. 盤面のCOREがすべて0になればクリア。装置が未使用でもクリア可能。
12. 複数の同時イベントはCORE / 装置IDの順で記録する。レンダラーの速度、乱数、実時刻は遷移結果に関与しない。

光球は経路変更装置の「座標＋進行方向＋装置状態」を記憶してループを止めます。分裂した光球は履歴を引き継ぎます。1遷移は2048生成光球と盤面サイズに比例するtick上限で停止します。上限到達を黙って正しいクリアとして扱わず `overflow` を返します。ゲームではそのタップを適用しません。Solverは危険な遷移を解答に使いません。

## 状態と描画

`State` はCORE HP、装置状態、使用タップ数を持ちます。探索のキーはHPと装置状態だけで、タップ数は含みません。同じ状態へ少ない手数で到達した経路を優先できます。盤面は生成完了後に変更しない契約です。変異・編集は新しいBoardオブジェクトを作ります（遷移エンジンは盤面形状をWeakMapにキャッシュします）。

遷移は `Next State + Timeline` を返し、85ms/cellを標準としてCanvasが再生します。描画中の操作をロックし、画面移動時はrequestAnimationFrameと再生待ちを終了します。Reduced Motionでは移動光球を描かず、短時間で状態変化を反映します。

## Solver

生存COREが12以下ならBFS。大きな状態では、遷移キャッシュと探索失敗深度を共有する深さ反復探索を使います。どちらも最短手数と最適初手集合を証明してから返します。探索予算に達した場合は `complete:false / par:null` です。

BFSのsolutionCountは同じ最短状態へ統合する経路数を加算します（上限10億）。深さ探索のsolutionCountは最適初手数による下限推定です。すべての最短経路数を正確に数えた値として利用しないでください。

生成WorkerとヒントWorkerを分離し、先読みがヒントを待たせないようにします。タイムアウト・Worker例外では該当Workerを再起動し、待機中のPromiseを失敗で解放します。

## Generator

FNV-1a（UTF-16 code unit）＋Mulberry32をGEN-V1として固定。`PC1-{mode}-{difficulty}-{key}` がルール・生成バージョンを指定します。modeはC/I/D、difficultyはE/N/H/X/Z。Campaignの難易度とDailyのNORMALは正規化します。

連鎖木の根から、既存COREにつながる射線上へ子COREを追加します。経路の一部を鏡・分裂器で曲げ、経路を予約し、ARMOR・後期装置・障害物への変異を加えます。Solverで変異後の盤面を証明し、12候補を比較します。難易度に応じて最短手数・起点比率・連鎖長を重視し、解答中に関与しない装置を減点します。

7つの盤面シルエット、章ごとの装置上限、難問の間の休憩ステージ、50ステージごとの大連鎖を用意します。初期300問はattempt/par/盤面hashで固定し、初登場14盤面は専用設計です。既存問題を変える改善はGEN-V2として追加してください。

品質検査には限界があります。装置の関与と必要性は同じではなく、現在の品質式は「その装置を除いたすべての最適解」を証明するアブレーション評価ではありません。回転対称をまとめるfingerprintと連鎖数列のsignatureをInspectorに表示しますが、過去全Campaignとの近似重複排除は未実装です。

## 保存

セーブv1はlocalStorage、問題キャッシュはIndexedDBに保存。キャッシュは120問題を上限にし、チェックサムと盤面検査後に読みます。キャッシュが使えなくても再生成できます。途中状態は生のHPを信頼せず、保存されたタップ列を共有エンジンで再生して復元します。

インポートは進行・最良手数・お気に入りをマージし、現在の記録を後退させません。保存不可は画面へ通知します。キャッシュを消してもステージ番号とコードから同じ問題が再生成されます。アカウント同期はありません。
