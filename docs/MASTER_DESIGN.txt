# 0. エグゼクティブサマリー


PULSE CHAINは、盤面上のCOREを1つタップすると発光するPULSE弾が複数方向へ走り、別のCOREへ命中するとそのCOREも起爆し、反射・分裂・耐久・障害物などを介して連鎖が広がっていく、1タップ中心の連鎖型ロジックパズルである。


プレイヤーの目的は、できるだけ少ないTAPで盤面上のCOREをすべて消去すること。


本企画の特徴は、単に無限に問題を生成することではない。SolverとQuality Gateを使い、**人間が遊んで「もう1問」と感じる良問を、AIなしで永久に生成する機械そのものを作る**ことを目標とする。


本番環境ではOpenAI API、LLM API、ユーザーDB、ログイン、常時稼働サーバーを使用しない。ゲーム、Solver、Generatorはユーザーのブラウザ内で動作し、GitHubでコード管理し、Cloudflare Pages等で静的配信する。


ゲームモードは以下を中核とする。


- 世界中のプレイヤーが同じ番号の問題を遊ぶCAMPAIGN
- 難易度指定で事実上無限に遊べるINFINITE MODE
- 日付seedから世界共通問題を生成するDAILY PUZZLE
- seed / Puzzle Codeによる完全再現・共有


本番稼働後の理想は、開発者が長期間新ステージを手作業で追加しなくても、Stage 10,000、Stage 100,000、Daily、Infiniteが継続して成立する状態である。

# 1. プロジェクトの目的


## 1.1 目指すゲーム


世界中の誰でも、


- 数秒でルールを理解できる
- 文字を読まなくても基本操作が分かる
- スマホでもPCでも遊べる
- 1問が短く、隙間時間でも遊べる
- 難問ではしっかり考えられる
- 1タップの結果を見るだけでも気持ちいい
- 「次の問題も見たい」が生まれる
- Campaignを長期的に進められる
- Campaign以外にも永久に新問題を遊べる


というパズルゲームを作る。


## 1.2 一文コンセプト


> **ひとつ押す。全部つながる。**


英語:


> **Tap one. Trigger them all.**


## 1.3 ジャンル


ミニマル・連鎖型ロジックパズル。


主な要素:


- 1タップ
- 連鎖
- 予測
- 反射
- 分岐
- 最小手数
- 幾何学的盤面
- 爽快なカスケード演出
- 世界共通Stage
- 手続き型生成

# 3. ゲームのコアルール


## 3.1 基本操作


プレイヤーが行う基本操作は1つ。


**盤面上のCOREをタップする。**


原則使わない操作:


- ドラッグ必須
- 長押し必須
- 精密スワイプ
- 2本指ジェスチャー


## 3.2 勝利条件


盤面上の破壊対象COREをすべて消去すればCLEAR。


## 3.3 TAP


プレイヤーがCOREを直接起爆する操作をTAPと呼ぶ。


各ステージにはSolverによる最小TAP数 `par` を持つ。


## 3.4 クリア評価


- PERFECT CASCADE: 最小TAPでCLEAR
- GREAT: 最小TAP + 1
- CLEAR: それ以上


Stage進行はCLEARだけで可能。Perfect強制はしない。


## 3.5 ONE TAP CASCADE


1 TAPで盤面全体を消した場合は特別扱いする。


旧PUSH/PULL案では「一手で終わる」は退屈だったが、CHAIN版では「一手で巨大な結果を設計できた」こと自体を報酬にする。

# 4. CORE


## 4.1 NORMAL CORE


HP = 1。


- 直接タップすると即起爆
- PULSEが1回命中すると起爆
- 起爆時に標準方向へPULSEを発射


標準方向:


```text
↖ ↑ ↗
← ● →
↙ ↓ ↘
```


8方向。


## 4.2 ARMOR CORE


HP = 2 または3。


中央に数字を表示する。


役割:


- 複数方向からPULSEを集める
- 連鎖の一時停止点になる
- 起爆タイミングを遅らせる
- 複数ルートを合流させる


ARMORは単なる耐久オブジェクトではなく、**連鎖タイミングを制御する蓄積装置**と考える。


---


# 5. PULSE


## 5.1 定義


PULSEはCORE起爆時に発生するエネルギー弾。


ロジック上はGridイベントだが、画面では**小さな発光球が実際に移動する**。


以前の試作で、単なる線エフェクトでは操作感・爽快感を評価できず、実際に発光球が盤面を走る版で明確に体験が改善したため、この仕様は必須とする。


## 5.2 移動


整数Gridを1セルずつ進む。


演出上の初期目安:


- 60〜100ms / cell
- 初期値 85ms / cell


Logicは速度に依存しない。


## 5.3 方向


標準COREは8方向。


- N
- NE
- E
- SE
- S
- SW
- W
- NW


将来特殊COREとして4方向、斜めのみ等を導入する場合も、初期ギミック群とは分離して検討する。


## 5.4 停止・変化条件


PULSEは以下で停止または挙動変更する。


- 盤面外
- VOID
- BLOCK
- CORE
- MIRROR
- SPLITTER
- GATE
- PORTAL
- その他状態ギミック


## 5.5 CORE命中


```text
HP -= 1
```


HP > 0:


- COREが膨張
- Flash
- 数字更新
- PULSE消滅


HP <= 0:


- 起爆予約
- 短いdelay
- 起爆
- 新しいPULSE群発生

# 6. 連鎖シミュレーション


## 6.1 Wave-based Simulation


複数のPULSEが同時に存在するため、処理順による結果差を防ぐ。


推奨:


```text
Wave 0
Player taps A


Wave 1
Aの全PULSEを評価
B / CへHit


Wave 2
Wave 1で起爆条件を満たしたCOREを起爆
D / E / FへHit


Wave 3
次の起爆群
```


同じState + 同じTapで必ず同じNext Stateになること。


## 6.2 Event Timeline


Transition Engineは結果だけでなく演出イベント列も返す。


例:


```json
{
  "events": [
    {"type":"core_charge","coreId":3},
    {"type":"core_explode","coreId":3},
    {"type":"pulse_spawn","pulseId":17},
    {"type":"pulse_move","pulseId":17,"from":[4,4],"to":[4,5]},
    {"type":"pulse_reflect","pulseId":17,"cell":[4,7]},
    {"type":"pulse_hit","pulseId":17,"coreId":8},
    {"type":"core_hp","coreId":8,"from":2,"to":1}
  ]
}
```


RendererはこのTimelineを再生するだけにする。

# 7. 基本ギミック


ギミックを無限に増やさない。


最終的な主要ギミックは8〜10種類程度に制限する。


## 7.1 BLOCK


PULSEを停止する。


反射しない。


見た目は重く、不透明で明確にする。


## 7.2 MIRROR


2種類。


```text
/
\
```


PULSEを90度反射する。


視覚と挙動を完全一致させる。


## 7.3 SPLITTER


PULSEを複数方向へ分裂させる。


分裂方向は形状で明示する。


SPLITTERによりPULSE数が指数増加し得るため、安全上限を設ける。


## 7.4 VOID


内部Grid上では位置があるが、盤面には存在しないセル。


PULSEはVOIDへ入ると消える。


用途:


- 非正方形盤面
- 射線制御
- ステージシルエット形成


## 7.5 GATE


特定方向からのみPULSEを通す。


後半用。


## 7.6 CHARGE


一定回数PULSEを受けると起動する中継装置。


破壊対象ではない。


## 7.7 ROTATOR


PULSE命中時に向きが変わる。


盤面に状態・記憶を持たせる高難度ギミック。


## 7.8 PORTAL


PULSEを別地点へ転送。


後半限定。


原則1ステージ1〜2pairまで。

# 11. Seedと再現性


## 11.1 Campaign Seed


例:


```text
PULSECHAIN|CAMPAIGN|RULE-V1|GEN-V3|12582|ATTEMPT-4
```


文字列をHashし、seeded PRNGへ渡す。


## 11.2 Puzzle Code


例:


```text
PC-8KM4-Q7RX
```


同じPuzzle Codeは永久に同じ問題を再現。


共有URL例:


```text
?p=8KM4Q7RX
```


## 11.3 PRNG


Math.random依存は禁止。


候補:


- xoshiro
- splitmix
- mulberry系


仕様として固定する。

# 13. Solver


SolverはPULSE CHAINの心臓部。


UIより先に完成させる。


## 13.1 最大原則


**GameとSolverは同じTransition Engineを使う。**


Solver側に別ルールを再実装しない。


## 13.2 State Model


最低限:


- 各COREのHP / alive
- ROTATOR向き
- CHARGE値
- GATE状態
- TAP数


アニメーション位置はStateに含めない。


## 13.3 Pure Transition Engine


入力:


```text
State + Tapped Core ID
```


出力:


```text
Next State + Event Timeline + Action Metadata
```


## 13.4 Determinism


同一State + 同一Tap = 同一結果。


Logicで浮動小数点物理を使わない。


## 13.5 Solver Algorithm


MVPはBFS。


必要に応じて:


- A*
- IDA*
- Bidirectional Search
- Transposition Table
- Zobrist Hash
- Symmetry Reduction


## 13.6 Solver用途


- 解答存在確認
- 最短TAP
- Hint
- Winning First Moves
- Solution Count推定
- Generator検証
- Difficulty
- Quality分析
- Regression Test


---


# 14. Puzzle Generator


## 14.1 最大原則


単純ランダム配置を主方式にしない。


本命は、


**Solution-first / Chain Graph Generation**


である。


## 14.2 Chain Graph


盤面を作る前に、気持ちいい連鎖構造を作る。


例:


```text
A
├── B
│   └── D
└── C
    └── E


D + E
   ↓
ARMOR F
   ↓
MIRROR
   ↓
G
   ↓
SPLITTER
├── H
└── I
```


## 14.3 Reverse Construction


CLEARから逆算する方式も検討。


```text
CLEAR
 ↑
Final Core
 ↑
Trigger Pair
 ↑
Previous Core
```


## 14.4 Generator Pipeline


```text
Seed
 ↓
Difficulty Profile
 ↓
Board Shape
 ↓
Chain Graph
 ↓
Graph Embedding
 ↓
Gimmick Placement
 ↓
Solver
 ↓
Difficulty Evaluation
 ↓
Quality Evaluation
 ↓
Mutation
 ↓
Final Candidate
```


## 14.5 Mutation


成立したCandidateを改善する。


例:


- CORE位置変更
- ARMOR値変更
- MIRROR移動
- VOID追加
- BLOCK追加
- SPLITTER方向変更


変更後は必ずSolver再検証。


## 14.6 Candidate Pool


Infiniteで1 Candidateを即採用しない。


難易度に応じて10〜50 Candidate程度を生成し、Quality上位を採用する。

# 16. Quality Model


DifficultyとQualityを分離する。


難しいから良問とは限らない。


## 16.1 Quality Features


- Chain Satisfaction
- Elegance
- Surprise
- Interaction Density
- Visual Clarity
- Dead Object Ratio
- Gimmick Necessity
- Trap Quality
- Max Chain
- Average Chain
- Ending Satisfaction
- Diversity


## 16.2 Chain Satisfaction


目安:


- 1〜2: 低
- 3〜5: 普通
- 6〜9: 良
- 10〜15: 高
- 16+: 非常に高


## 16.3 Dead Object Ratio


最適解に関与しないCOREやギミックが多い問題は低評価。


## 16.4 Gimmick Necessity


MIRRORが配置されているのに解答で使わない場合は低評価。


SPLITTERを使わなくても同等解がある場合も要評価。


## 16.5 Surprise


良いSurpriseは、


**予想外だが、結果を見れば理解できる。**


ランダムで意味不明な挙動は評価しない。


## 16.6 Trap Quality


良い失敗:


```text
あと1個残った
```


悪い失敗:


```text
なぜ詰んだのか理解できない
```


## 16.7 排除対象


- 小連鎖のみ
- 特殊ギミックが飾り
- 起点が自明すぎる
- COREが独立
- ARMORが無意味
- 同型配置の連続
- 視認性が悪い
- 総当たり以外に考え方がない
- 高難度なのに演出報酬が弱い

# 22. Audio / Haptics


Web Audio API推奨。


Chainが増えるごとにPitchを少し上げる。


上限を設け、不快な高音化を避ける。


設定:


- Sound ON/OFF
- Volume
- Reduced Sound

# 62. 現在までの試作で得た知見


## 62.1 旧PUSH/PULL案


磁力PUSH/PULL型は、


- 1操作の結果が大きすぎる
- 途中状態が浅い
- 連鎖が弱い
- 類似パズルが既に存在する
- 爽快感が不足


という理由から正式核から外した。


## 62.2 CHAIN案


COREから発光球が実際に走り、他COREへ命中して連鎖する版では、明確に爽快感が上がった。


## 62.3 演出知見


単なる光線描画だけでは不十分。


プレイヤーが**「何かが盤面を移動している」**と感じる必要がある。


## 62.4 盤面知見


正方形固定より、Wide / Diamond / Cross / Ring / Irregular等の方が「次の盤面を見たい」という期待につながる。


## 62.5 ギミック知見


MIRRORとSPLITTERは、見た目とロジックが一致し、連鎖演出にも寄与するため有望。
